# 修正要望サイト 導入手順（卒研リポジトリ側）

修正要望サイト（`tarutoon7391/sotsuken-request`）からの要望を、この リポジトリで自動修正するための設定です。
サイト側の説明と Railway へのデプロイ手順はサイトのリポジトリの README を参照してください。

> **2026-11 更新：自動修正の仕組みを `anthropics/claude-code-action` から Agent SDK（`@anthropic-ai/claude-agent-sdk`）で自作した Issue-Agent に置き換えました。**
> 理由：Claude Code Action は Anthropic Console の promo credit の対象外ですが、Agent SDK 経由の API 利用は対象になるためです。
> Claude GitHub App のインストールは不要になりました。

## 全体の流れ

```
要望サイト ──Issue 作成（ラベル request-site / type:* / screen:*）──▶ Sotsuken
                                                                      │
                                      .github/workflows/claude.yml が起動
                                      → node scripts/issue-agent/index.mjs（Agent SDK）
                                         ① ブランチ claude/issue-N を用意
                                         ② Claude が許可パス内を修正
                                         ③ npm run build
                                         ④ 許可パス外の差分があれば取り消して中止
                                         ⑤ commit → push → gh pr create（Closes #N、ラベルは Issue と同じ）
                                         ⑥ Issue にコメント（成功: PR URL / 失敗: 理由）
                                                                      │
                                      .github/workflows/pr-checks.yml
                                      → type:style：許可パス以外の変更があれば失敗
                                      → type:bug  ：npm test とテスト追加が無ければ失敗
                                      → type:feature：client/src/ 外の変更か npm test の失敗で失敗
                                                                      │
                                      人がレビュー（最低1人）→ main にマージ
```

## Claude Code Action からの変更点

| 項目 | 旧（claude-code-action） | 新（Issue-Agent / Agent SDK） |
|---|---|---|
| 実行主体 | `anthropics/claude-code-action@v1` | `scripts/issue-agent/index.mjs`（`@anthropic-ai/claude-agent-sdk` の `query()`） |
| 起動条件 | Issue 本文・コメントの `@claude` | Issue に `request-site` ラベルが付いたとき（opened / labeled）。コメントは `@claude` を含み、コメント主が OWNER / MEMBER / COLLABORATOR のときだけ |
| 必要な GitHub App | Claude GitHub App のインストール | 不要 |
| 必要な Secrets | `ANTHROPIC_API_KEY` | `ANTHROPIC_API_KEY`（必須）、`ISSUE_AGENT_GH_TOKEN`（任意・後述） |
| commit / push / PR 作成 | Claude 自身が実行 | スクリプトが実行（Claude には許可パス内の編集・build・test だけさせる） |
| 許可パスの検査 | PR 作成後に pr-checks.yml で失敗させる | **PR を作る前に**スクリプトが検査し、許可パス外があれば変更を取り消して中止（pr-checks.yml は二重の保険として残す） |
| モデル | type:bug / type:feature は Opus、他は Sonnet | **type:bug は `claude-opus-5-5`、それ以外は `claude-sonnet-5`** |
| 上限 | `--max-turns 60` | 50 ターン・全体 20 分（超えたら中断して Issue にコメント） |
| 結果の報告 | Claude が Issue にコメント（進捗つき） | スクリプトが 1 回だけコメント（SDK の出力は貼らない） |
| コスト | Actions のログに出ない | スクリプトが `total_cost_usd` を Actions のログに出す |
| 同時実行 | 制限なし | 同じ Issue 番号の実行は 1 本だけ（新しい実行が来たら古い方を止める） |

Issue 本文は「信頼できない入力」として `<issue_body>` タグで囲んで Claude に渡し、本文中の命令文（「〜を削除しろ」「設定を変えろ」など）には従わないよう指示しています。
また Claude には `.env`・トークン・鍵を読ませない設定（`.claude/settings.json` の deny と、システムプロンプトでの指示）になっています。

## 追加・変更したファイル

| ファイル | 役割 |
|---|---|
| `scripts/issue-agent/index.mjs` | Issue-Agent 本体。環境変数（`ISSUE_NUMBER` / `ISSUE_TITLE` / `ISSUE_BODY` / `ISSUE_LABELS` / `REPO` / `ANTHROPIC_API_KEY` / `GITHUB_TOKEN`）を受け取り、Agent SDK で修正 → build → 差分検査 → commit → push → PR → Issue コメント |
| `.github/workflows/claude.yml` | 上のスクリプトを呼ぶワークフロー（`request-site` ラベル / `@claude` コメントで起動） |
| `.github/workflows/pr-checks.yml` | PR チェック（`見た目PR 許可パスチェック`・`バグPR テスト`・`機能追加PR 許可パス・テスト`）。該当しない種別の PR では対象外として成功 |
| `client/vitest.setup.js`、`client/vite.config.js` の `test`、`client/src/test/*.test.{js,jsx}` | クライアント側のテスト環境（vitest + jsdom + testing-library）。`npm test` でサーバー（jest）→クライアント（vitest）の順に走る |
| `CLAUDE.md` の「自動修正 PR のルール」節 | Claude が Issue から修正するときの規約（Issue-Agent は `settingSources: ["project"]` で CLAUDE.md を読み込む） |
| `package.json` の `devDependencies` | `@anthropic-ai/claude-agent-sdk` を追加（`npm ci` で入る。claude の実行ファイルも同梱） |

## 1. Secrets の登録（リポジトリ admin が行う）

1. Anthropic Console で API キーを発行する（promo credit があるワークスペースのキー）
2. リポジトリの **Settings → Secrets and variables → Actions → New repository secret** で `ANTHROPIC_API_KEY` を登録する
3. **任意（推奨）**：`ISSUE_AGENT_GH_TOKEN` を登録する
   - GitHub の仕様で、Actions 既定の `GITHUB_TOKEN` で作った PR では **`pull_request` イベントのワークフロー（pr-checks.yml）が自動で走りません**。ブランチ保護で pr-checks を必須にしている場合、チェックが「待機中」のままマージできなくなります
   - 回避策として、`contents: write`・`pull-requests: write`・`issues: write` を持つ Fine-grained PAT（対象リポジトリ：Sotsuken のみ）を `ISSUE_AGENT_GH_TOKEN` として登録すると、ワークフローはそちらで checkout / push / PR 作成を行い、pr-checks が通常どおり走ります
   - 登録しない場合は、PR を一度 Close → Reopen するか、空コミットを push すると pr-checks が走ります
4. **Settings → Actions → General** で Actions が有効になっていること、Workflow permissions が「Read and write」になっていることを確認する

> Claude Pro/Max の OAuth トークン（`claude setup-token`）は Agent SDK では使えません。必ず Console の API キーを使ってください。

## 2. ラベル

要望サイトが Issue 作成時に無いラベルを自動で作るので、事前作成は不要です。
手で作る場合は次の名前にしてください：`type:style`、`type:bug`、`type:feature`、`needs-human`、`screen:student`、`screen:teacher`、`screen:popup-away`、`screen:class`、`screen:auth`、`screen:other`、`request-site`。

Issue-Agent は `type:*` ラベルで動作を切り替えます。`type:*` が無い Issue はコメントを残して何もしません。

## 3. ブランチ保護（main への直 push 禁止・レビュー必須・CI 必須）

GitHub の **Rulesets** で設定します（Settings → Rules → Rulesets → New ruleset → New branch ruleset）。

1. **Ruleset Name**：`main 保護`、**Enforcement status**：Active
2. **Target branches**：Add target → Include default branch
3. **Rules** で次にチェック
   - ☑ **Restrict deletions**
   - ☑ **Require a pull request before merging**
     - Required approvals：**1**
     - ☑ Dismiss stale pull request approvals when new commits are pushed
   - ☑ **Require status checks to pass**
     - ☑ Require branches to be up to date before merging
     - Add checks で次を追加（一度 PR を作って CI が走ると候補に出ます）
       - `見た目PR 許可パスチェック`
       - `バグPR テスト`
       - `機能追加PR 許可パス・テスト`
   - ☑ **Block force pushes**
4. **Bypass list** は空のまま（オーナーも直 push しない。緊急時だけ一時的に自分を足す）
5. Create

> 注意：Issue-Agent が作る PR の作者は `github-actions[bot]`（`ISSUE_AGENT_GH_TOKEN` を使う場合はその PAT の持ち主）です。チームの誰か 1 人が Approve すればマージできます。
> レビューした人がマージ担当です。マージ後は Railway が main から自動デプロイします。

## 4. 動作確認の手順

1. 要望サイトにログインし、「見た目」で簡単な要望（例：ログイン画面のボタン余白を広げる）を送る
2. Sotsuken の Issues に `[見た目] ログイン・登録: …` が作られ、ラベル `type:style` `screen:auth` `request-site` `requester:<名前>` が付いていることを確認
3. Actions タブで「Claude Issue Agent」が走り、数分後に PR が作られ、Issue に `✅ PR を作成しました: …` とコメントが付くことを確認
   - Actions のログの `result: … cost_usd=…` 行でその実行のコストが分かる
4. PR の Checks に `見た目PR 許可パスチェック` が出て成功することを確認
   - わざと CSS 以外を変えた PR を手で作ると失敗することも確認できる
5. 「バグ」でも同様に送り、PR に `*.test.js` / `*.test.jsx` の追加があり `バグPR テスト` が通ることを確認
6. 要望サイトの一覧で状態が「PR作成済み」→ マージ後「マージ済み」に変わることを確認
7. 既存の Issue に `@claude ○○も直してください` とコメントすると、同じ `claude/issue-N` ブランチの続きから修正され、既存 PR に追加されることを確認

## 5. コストの目安

Anthropic API の定価（2026-10 時点）：

| モデル | 入力 / 1M tok | 出力 / 1M tok | 使う場面 |
|---|---|---|---|
| `claude-sonnet-5` | $2 | $10 | type:style / type:feature |
| `claude-opus-5-5` | $4 | $20 | type:bug |

1 回の実行は、コードの読み込み量とターン数で大きく変わりますが、目安は次のとおりです（プロンプトキャッシュが効くため入力の大半は 1/10 の単価になります）。

| 種別 | 典型的なターン数 | 目安 |
|---|---|---|
| 見た目（CSS 数行） | 10〜20 | 約 $0.2〜0.8 |
| 機能追加（小さい部品） | 20〜40 | 約 $0.5〜2 |
| バグ（テスト追加＋修正、Opus） | 20〜50 | 約 $1〜5 |

実際の金額は Actions のログの `cost_usd=` と、Anthropic Console の Usage で確認してください。
上限は 1 実行あたり 50 ターン・20 分なので、暴走しても 1 回で数ドルを超えることはほぼありません。

## 6. うまく動かないとき

| 症状 | 確認すること |
|---|---|
| Issue が作られたのに Actions が走らない | Issue に `request-site` ラベルがあるか。Issue を作ったのが PAT（要望サイトの `GITHUB_TOKEN`）か。Actions 既定の `GITHUB_TOKEN` で作った Issue ではワークフローが起動しない（GitHub の仕様） |
| `@claude` とコメントしても走らない | コメント主がリポジトリの OWNER / MEMBER / COLLABORATOR か。PR のコメントでは起動しない |
| `Issue-Agent を実行` ステップが `環境変数 ANTHROPIC_API_KEY がありません` で落ちる | Secrets に `ANTHROPIC_API_KEY` が登録されているか |
| `Native CLI binary for linux-x64 not found` | SDK 同梱の実行ファイルが入らなかった。ワークフローが `npm i -g @anthropic-ai/claude-code` を入れているので、`env` に `CLAUDE_CODE_PATH: $(which claude)` 相当を足す |
| Issue に `❌ 許可パス外のファイルが変更された…` とコメントされた | 要望が許可パスの中だけでは実現できない。人が対応するか、要望を見直す |
| Issue に `❌ 20 分の制限時間内に…` とコメントされた | 要望を小さく分けて送り直す |
| PR はできたが pr-checks が走らない | `ISSUE_AGENT_GH_TOKEN` が未登録（上記 1-3）。PR を Close → Reopen すると走る |
| `種別を判定` が失敗 | PR にラベルが無く本文に `Closes #N` も無い。PR にラベル `type:style` / `type:bug` / `type:feature` を手で付ける |
| 要望サイトの一覧に PR が出ない | PR のブランチが `claude/issue-N` でなく本文にも `#N` が無い。PR 本文に `Closes #N` を足す |

## 7. 許可パスを変えたいとき

次の 3 か所を同時に変更してください。

- `scripts/issue-agent/index.mjs` の `ALLOWED_PATHS` / `FORBIDDEN_PATHS` / `KIND_FORBIDDEN`
- `.github/workflows/pr-checks.yml` の `ALLOWED_PATTERNS`
- 要望サイト `src/issueBody.js` の `STYLE_ALLOWED_PATHS` / `FEATURE_ALLOWED_PATHS`（Issue の指示文に出る）

## 8. 手元で動かすとき（デバッグ用）

GitHub Actions と同じ環境変数を渡せばローカルでも動きます（`gh` CLI と Node.js 20 以上が必要）。
実際に push と PR 作成まで行うので、試すときは別リポジトリか捨てブランチで。

```bash
export ANTHROPIC_API_KEY=sk-ant-...
export GITHUB_TOKEN=ghp_...            # gh と git push に使う
export REPO=tarutoon7391/Sotsuken
export ISSUE_NUMBER=49
export ISSUE_TITLE="$(gh issue view 49 --json title --jq .title)"
export ISSUE_BODY="$(gh issue view 49 --json body --jq .body)"
export ISSUE_LABELS="$(gh issue view 49 --json labels --jq '[.labels[].name] | join(",")')"
node scripts/issue-agent/index.mjs
```
