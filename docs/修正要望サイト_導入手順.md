# 修正要望サイト 導入手順（卒研リポジトリ側）

修正要望サイト（`tarutoon7391/sotsuken-request`）からの要望を、この リポジトリで自動修正するための設定です。
サイト側の説明と Railway へのデプロイ手順はサイトのリポジトリの README を参照してください。

## 全体の流れ

```
要望サイト ──Issue 作成（末尾に @claude 指示、ラベル type:*/screen:*）──▶ Sotsuken
                                                                      │
                                      .github/workflows/claude.yml が起動
                                      → claude/issue-N-… ブランチに修正を push
                                      → gh pr create（ラベル付き、Closes #N）
                                                                      │
                                      .github/workflows/pr-checks.yml
                                      → type:style：許可パス以外の変更があれば失敗
                                      → type:bug  ：npm test とテスト追加が無ければ失敗
                                      → type:feature：client/src/ 外の変更か npm test の失敗で失敗
                                                                      │
                                      人がレビュー（最低1人）→ main にマージ
```

## 追加したファイル

| ファイル | 役割 |
|---|---|
| `.github/workflows/claude.yml` | Claude Code Action。Issue 本文やコメントの `@claude` で起動。公式 `anthropics/claude-code-action@v1` の examples/claude.yml 準拠 |
| `.github/workflows/pr-checks.yml` | PR チェック（`見た目PR 許可パスチェック` と `バグPR テスト` の2ジョブ）。該当しない種別の PR では対象外として成功 |
| `client/vitest.setup.js`、`client/vite.config.js` の `test`、`client/src/test/*.test.{js,jsx}` | クライアント側のテスト環境（vitest + jsdom + testing-library）。`npm test` でサーバー（jest）→クライアント（vitest）の順に走る |
| `CLAUDE.md` の「自動修正 PR のルール」節 | Claude が Issue から修正するときの規約 |

## 1. Claude GitHub App のインストールと Secrets（リポジトリ admin が行う）

公式手順（anthropics/claude-code-action の docs/setup.md）どおりです。

1. https://github.com/apps/claude を開き、`tarutoon7391/Sotsuken` にインストールする
2. Anthropic Console で API キーを発行する
3. リポジトリの **Settings → Secrets and variables → Actions → New repository secret** で `ANTHROPIC_API_KEY` を登録する
   - Claude Pro/Max の人は代わりに `claude setup-token` で作ったトークンを `CLAUDE_CODE_OAUTH_TOKEN` として登録し、`claude.yml` の `anthropic_api_key` 行を `claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}` に差し替える
4. **Settings → Actions → General** で Actions が有効になっていることを確認する

別の方法として、ローカルの Claude Code で `/install-github-app` を実行すると 1〜3 をまとめて案内してくれます。

## 2. ラベル

要望サイトが Issue 作成時に無いラベルを自動で作るので、事前作成は不要です。
手で作る場合は次の名前にしてください：`type:style`、`type:bug`、`type:feature`、`needs-human`、`screen:student`、`screen:teacher`、`screen:popup-away`、`screen:class`、`screen:auth`、`screen:other`、`request-site`。

## 3. ブランチ保護（main への直 push 禁止・レビュー必須・CI 必須）

GitHub の **Rulesets** で設定します（Settings → Rules → Rulesets → New ruleset → New branch ruleset）。

1. **Ruleset Name**：`main 保護`、**Enforcement status**：Active
2. **Target branches**：Add target → Include default branch
3. **Rules** で次にチェック
   - ☑ **Restrict deletions**
   - ☑ **Require a pull request before merging**
     - Required approvals：**1**
     - ☑ Dismiss stale pull request approvals when new commits are pushed
   - ☑ **Require status checks to pass**
     - ☑ Require branches to be up to date before merging
     - Add checks で次の2つを追加（一度 PR を作って CI が走ると候補に出ます）
       - `見た目PR 許可パスチェック`
       - `バグPR テスト`
   - ☑ **Block force pushes**
4. **Bypass list** は空のまま（オーナーも直 push しない。緊急時だけ一時的に自分を足す）
5. Create

> 注意：Claude が作る PR は `claude[bot]` が作者なので、チームの誰か1人が Approve すればマージできます。
> レビューした人がマージ担当です。マージ後は Railway が main から自動デプロイします。

## 4. 動作確認の手順

1. 要望サイトにログインし、「見た目」で簡単な要望（例：ログイン画面のボタン余白を広げる）を送る
2. Sotsuken の Issues に `[見た目] ログイン・登録: …` が作られ、ラベル `type:style` `screen:auth` `request-site` `requester:<名前>` が付いていることを確認
3. Actions タブで「Claude Code」が走り、数分後に PR が作られることを確認（Issue のコメントに進捗が出る）
4. PR の Checks に `見た目PR 許可パスチェック` が出て成功することを確認
   - わざと CSS 以外を変えた PR を手で作ると失敗することも確認できる
5. 「バグ」でも同様に送り、PR に `*.test.js` / `*.test.jsx` の追加があり `バグPR テスト` が通ることを確認
6. 要望サイトの一覧で状態が「PR作成済み」→ マージ後「マージ済み」に変わることを確認

## 5. うまく動かないとき

| 症状 | 確認すること |
|---|---|
| Issue が作られたのに Actions が走らない | Issue 本文に `@claude` があるか。Issue を作ったユーザー（要望サイトのトークンの持ち主）が write 権限を持っているか。`GITHUB_TOKEN` で作った Issue では起動しない（公式 FAQ） |
| Claude がブランチを push したが PR ができない | `claude.yml` の `--allowedTools` に `Bash(gh pr create:*)` があるか。Claude のコメントに PR 作成リンクが出ていればそこから手で作ってもよい |
| `見た目PR 許可パスチェック` が失敗 | Claude が許可パス外を変えた。Issue にコメントで `@claude 許可パス外の変更を元に戻してください` と指示する |
| `種別を判定` が失敗 | PR にラベルが無く本文に `Closes #N` も無い。PR にラベル `type:style` / `type:bug` / `type:feature` を手で付ける |
| 要望サイトの一覧に PR が出ない | PR のブランチが `claude/issue-N-…` でなく本文にも `#N` が無い。PR 本文に `Closes #N` を足す |

## 6. 許可パスを変えたいとき

次の2か所を同時に変更してください。

- `.github/workflows/pr-checks.yml` の `ALLOWED_PATTERNS`
- 要望サイト `src/issueBody.js` の `STYLE_ALLOWED_PATHS`（Issue の指示文に出る）
- `.github/workflows/claude.yml` の `--append-system-prompt` 内の記述
