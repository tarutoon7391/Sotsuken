## 1. コンセプト

**先生が授業を回すために設計された、低遅延・双方向のオンライン授業アプリ。**
配信・チャット・出席・理解度・質問箱が1画面に統合されており、
Zoom/Meet のような汎用会議ツールでは分散してしまう「授業運営」の操作を一体化する。

### 既存ツールとの差別化ライン（発表で聞かれる前提）
- Zoom/Meet：汎用会議ツール。出席・理解度・質問管理は別ツールや口頭に頼る
- 本アプリ：**授業専用設計**。出席（一時退出・欠課判定）、理解度のリアルタイム可視化、
  雑談と分離した質問箱、授業内資料表示、確認ボタンが標準搭載。
  生徒同士は顔が見えない（先生のみ見える）など、授業の場に合わせた視界設計

## 2. ユーザー区分（ロール）

| ロール | できること |
|---|---|
| 先生 | クラス作成、授業の開始/終了、配信、全生徒の映像閲覧、スポットライト、出席管理、確認ボタン発動、質問への回答、資料配布 |
| 生徒 | 参加コードでクラスに加入、授業の視聴、カメラON（先生のみに届く）、チャット・理解リアクション・質問、確認ボタン応答 |

- **ゲストは廃止**。全員ログイン必須（出席を取るため）。登録時にロールを選択する
  （※学校内利用前提。本運用なら管理者承認を挟む想定）
- 名前の下にロールバッジ（「先生」「生徒」）を表示する
- 発表会場のデモは「体験用クラス」の参加コードを配って即登録・即参加で行う

## 3. 用語

| 用語 | 意味 |
|---|---|
| クラス | 先生が作る授業のグループ。参加コードで生徒が加入する |
| 授業（レッスン） | クラス内で行う1回の配信セッション。LiveKit のルームと1対1対応 |
| スポットライト | 先生が指定した生徒の映像を全員に表示する状態（発表時） |

## 4. 機能要件（MVP）

### F-01 アカウント
- 会員登録（表示名・ログインID・パスワード・ロール）、ログイン/ログアウト、アイコン設定
- 名前の下にロールバッジを表示

### F-02 クラス・授業管理（先生）
- クラス作成（クラス名）→ 参加コード自動発行。生徒はコード入力で加入
- クラス内で授業を作成・開始・終了（タイトル・**タグ（任意、複数可）**）。**1クラスにつき同時開催は1授業まで**
- タグは科目・単元などを想定（例：「数学」「二次関数」）。授業一覧をタグで絞り込める。アーカイブ（S-03）にも引き継がれる
- 授業一覧（開催中／終了済み）と、クラスのメンバー一覧

### F-03 配信・視聴（全員カメラON対応）
- 先生：ブラウザから画面キャプチャ／カメラで配信（遅延1秒未満目標）
- 生徒：任意でカメラON。**生徒の映像は先生にのみ届き、他の生徒には配られない**
  （クライアント側の表示制御ではなく、配信基盤の購読権限で強制する）
- 先生画面：全生徒の映像をグリッド表示（低画質・小サイズ）
- **スポットライト**：先生が生徒を1人指定すると、その生徒の映像が全員に表示される（発表用）。解除も先生
- アーカイブ（S-03）に含めるのは先生の映像・音声のみ。生徒の映像は録画しない

### F-04 出席（v4：累積方式）
- 授業への入室時刻を自動記録。状態は **出席／一時退出／欠課** の3つ
- **一時退出ボタン**：押すと一時退出。「戻る」で復帰
- **回線切断も一時退出扱い**（離席か切断かを区別しない）
- **欠課判定は授業全体の退出時間の累積で行う**：
  - 復帰のたびに「今回の退出時間」を累積退出時間に加算する
  - 「累積退出時間 ＋ 現在退出中の経過時間」が閾値（既定15分、先生が変更可）を超えた時点で欠課
  - これにより「14分退出→1分復帰」の繰り返しで欠課を回避することができない
- 判定はサーバー側タイマー（1分間隔）で行う（生徒がブラウザを閉じても動く）
- 一時退出中画面には「欠課までの残り時間」を累積ベースで表示する（過去の退出分だけ短くなる）
- 先生は出席一覧で各生徒の累積退出時間を確認でき、状態を手動修正できる
- 授業終了時点で一時退出中の生徒は、今回分を累積に足したうえで **閾値以上なら欠課、未満なら出席**に確定する（最終結果は出席／欠課の2値）
- 残り時間が0になったあとの「戻る」は、タイマーの判定を待たずにその場で欠課にする
- 一度も入室しなかったクラスメンバーは、授業終了時に欠課として記録する
- 出席を記録するのは授業の開催中だけ。開始前の待機画面にいる生徒は、授業開始の時点で出席になる

### F-05 確認ボタン（受講確認）
- 先生が任意のタイミングで「確認」を発動（＋N分ごとの自動発動を設定可）
- 生徒画面にポップアップが出て、**制限時間（既定60秒）内にボタンを押す**と応答記録
- 未応答者は先生画面に一覧表示。未応答＝即欠課にはしない（先生判断で出席状態を修正）

### F-06 理解リアクション
- 生徒：「わかった／わからない／もう一度」ボタン
- 先生画面：現在の集計をリアルタイム表示（人数・割合）。一定時間で自動リセット or 先生が手動リセット

### F-07 質問機能
- **質問ボタン**：生徒が押すと先生画面に挙手通知（誰が挙手中か一覧）
- **質問箱**：雑談チャットと分離した質問専用チャンネル。先生は「回答済み」マークを付けられる
- **匿名投稿**：質問ごとに匿名トグル。匿名でも先生には投稿者が分かる（荒らし対策）、他の生徒には表示しない

### F-08 チャット（添付対応）
- テキストに加え、**画像・PDF・Office文書**を添付できる（1ファイル10MB程度まで）
- 動画ファイルの添付は対象外（URL貼付で代替。S-03 の R2 導入後に再検討）
- 投稿にはアイコン＋名前＋ロールバッジを表示

### F-09 授業内資料表示
- 先生が授業に資料（PDF・画像）をアップロードすると、生徒の視聴画面の横に資料パネルとして表示される
- 生徒は画面外で資料を開かずに授業を受けられる。ページ送りは各自（同期は S-06）
- 資料・添付は授業終了後も授業に紐づいて保持され、終了済み授業の詳細から閲覧できる（復習用）
- 先生は自分がアップした資料を削除できる。授業・クラス削除時は紐づくファイルも削除する

### F-10 プログラミングモード（拡張機能・v4.5・2026-10-31）

> 位置づけ：**MVP ではなく拡張機能**（発表の目玉候補）。MVP の修正と並行して着手してよい。契約は docs/04 §7、DB は docs/03 v4.5、画面は docs/07 §15。実装の段階・担当は docs/11 §5。

先生が授業中に「プログラミングモード」を起動すると、生徒の視聴画面の映像エリアがコードエディタに切り替わる。生徒はブラウザ上で Java を書き、保存・コンパイル・実行ができる。先生は全生徒のコードを一覧で監視し、エラーのある生徒をその場で把握し、必要なら生徒のエディタを直接編集できる。

- **モード**：授業ごとに `video`（通常）／`coding`。先生が切替。coding 中も生徒カメラは先生に送り続ける（先生は映像グリッド／コードグリッドをタブで切替）
- **課題（task）**：1授業に複数。先生が「タイトル＋テンプレートコード」で追加。先生が「今の課題」を指定すると全生徒のエディタがそのタブに切り替わる。生徒は過去の課題タブに戻れる
- **エディタ**：CodeMirror 6。Java のハイライトと構文解析（Lezer）。構文エラーは打っている最中からリアルタイム検出
- **保存（Ctrl+S / ⌘S / ボタン）**：コードを保存し、同時にコンパイルのみ実行。結果（成功／エラー行・メッセージ）を本人と先生に返す
- **実行（▶ボタン）**：コンパイル＋実行。標準入力欄あり。stdout / stderr / 終了コード / 実行時間を本人と先生に返す
- **制限**：CPU 10 秒、メモリ 256MB、出力 64KB、ネットワーク遮断、同時実行 4 本（超過は待ち行列、「実行待ち N 人」を表示）、1 生徒あたり 1 分に 6 回まで（値は `shared/constants.js` の `CODE_LIMITS`）
- **先生の監視**：コードグリッド（生徒ごとにコード先頭 20 行の縮小表示）。状態で枠色を変える：構文エラー＝赤／コンパイルエラー＝赤＋行番号／実行時エラー＝橙／正常終了＝緑チェック／未保存＝グレー
- **先生の編集**：セルをクリックで拡大。拡大中の生徒 1 人のエディタを**直接編集**できる（Yjs による共同編集。生徒側はロックせず打ち続けられる）。生徒画面に「先生が編集中」バッジと先生カーソル（色付き）を表示
- **コードスポットライト**：先生が 1 人のコードを指定すると全員の画面に表示（映像のスポットライトと同じ概念）。解除も先生
- **保存履歴**：保存ごとに履歴を残す。先生が編集して保存した場合は `edited_by_teacher` で区別
- **授業後**：生徒は自分の最終コードをクラス詳細→授業から閲覧・コピーできる。他人のコードは見えない。先生は授業結果画面で課題ごとの「コンパイル成功人数」「保存回数の分布」「最初にコンパイルが通った時刻」を見られる
- **対応言語**：`java` のみ（`language` 欄は持つ）。ファイルは `Main.java` 1 本固定、クラス名 `Main` 必須

**スコープ外**：複数ファイル・パッケージ・外部ライブラリ／デバッガ／Java 以外／生徒同士の共同編集／自動採点（S-02 と合体させる案は将来）

**非機能（F-10 固有）**
- 生徒のコードは**アプリサーバー上で実行しない**。必ず隔離された実行サーバー（Piston。開発は公開 API、本番は VPS でセルフホスト）に転送する
- 実行サーバーが落ちてもエディタ・保存・先生の監視は動き続ける（実行だけ「接続できません」）
- Yjs の同期サーバー（y-websocket）はアプリサーバーに同居。接続時にセッション・クラス所属・課題の存在を検証し、不正なら切断

## 5. 機能要件（ストレッチ）※優先順

1. **S-01 理解度の時系列グラフ**：授業中の「わからない」の推移を分単位で可視化。振り返り用
2. **S-02 ミニテスト**：授業終了時に選択式クイズ→自動採点→結果表示
3. **S-03 復習アーカイブ**：v2 で確定した仕様（保存期限 7/30/90日・削除・期限ルール・競合対策）をそのまま流用。公開範囲は「クラス内のみ／非公開」の2段階に簡略化。**タグ付け対応（v4）**：授業に付けたタグ（科目・単元など）がアーカイブにも引き継がれ、クラス内のアーカイブ一覧をタグで絞り込める
4. **S-04 課題の配布・提出**：先生がファイル＋期限で課題を配布、生徒がファイル提出、先生が提出状況一覧を確認（採点・コメントは対象外）
5. **S-05 文字起こし**：先生ブラウザの Web Speech API で音声→字幕化し配信（外部AI費用ゼロ）
6. **S-06 資料のページ同期**：先生がめくったページに生徒側も追従
7. **S-07 グループワーク部屋分け**：先生が生徒を音声のみの小部屋に手動で振り分ける最小版
8. **S-08 アーカイブの前後カット**：公開前に開始/終了位置を指定してトリミング（サーバー側 ffmpeg）。フル編集は対象外

## 6. アーカイブ（S-03）の期限ルール

v2 で確定した内容を継承する（要点のみ）：
- `expires_at = 授業終了日時 + 選択期間`。期間変更時も終了日時基準で再計算
- 過去日になる変更は不可（UIグレーアウト＋サーバー400＋削除提案）
- 期限判定は `expires_at` で即時。日次バッチは物理削除のみ。条件付きSQLで競合を防ぐ
- 古い画面からの操作は「期限が切れたため削除されました」表示で画面更新
- 日時は UTC 保存・JST 表示。テストケースは v2 §6 と同じ

### 出席（累積方式）のテストケース
- 10分退出→復帰→10分退出：2回目の退出開始から5分で欠課になること（累積20分＞15分）
- 14分退出→1分復帰→14分退出：2回目の退出開始から1分で欠課になること
- 復帰時に累積退出時間が正しく加算され、away_since がクリアされること
- 一時退出中画面の残り時間が「閾値 − 累積 − 現在の経過」で表示されること
- 回線切断→再接続でも同様に累積されること
- 先生が閾値を変更した場合、以降の判定に反映されること

## 7. 非機能要件

| 項目 | 目標 | 備考 |
|---|---|---|
| 遅延 | 先生映像の視聴で1秒未満 | |
| 同時参加 | 1授業あたり生徒30人程度（全員カメラON含む）を安定動作 | 生徒映像は低画質（〜300kbps）で先生側受信10Mbps前後を想定 |
| 対応ブラウザ | Chrome / Edge / Safari(iOS) 最新 | 先生側は Chrome 推奨 |
| 可用性 | 授業中に落ちない。切断時は自動再接続＋出席は一時退出扱い | |
| セキュリティ | bcrypt / LiveKitシークレット非公開 / ユーザー入力のエスケープ / **クラス外のユーザーは授業にアクセス不可** / **生徒映像の購読制限を基盤側で強制** | |
| プライバシー | 生徒映像は録画しない。匿名質問の投稿者は先生のみ閲覧可。生徒のコード（F-10）は本人と先生のみ閲覧可（コードスポットライト中を除く） | |
| コード実行の隔離（F-10） | 生徒のコードはアプリサーバーで実行しない。隔離された実行サーバー（Piston）に転送し、CPU・メモリ・出力・ネットワークを制限 | 実行サーバー停止時もエディタ・保存・監視は動く |
| ファイル | 添付・資料は Railway Volume。動画（アーカイブ）は R2 | |
| コスト | 通常月1,000円以内 | |

## 8. デモ要件（発表当日）

- 会場を「体験用クラス」にして、来場者が参加コードで即参加 → 理解リアクション・質問箱・確認ボタンを体験
- 先生役の発表者画面（生徒グリッド・理解度集計・出席一覧）を投影し、スポットライトで来場者を映すデモ
- 会場ネットワーク対策（テザリング切替）・録画の保険は従来どおり

## 9. 作らないもの（スコープ外）

- メール認証・パスワードリセット
- 生徒同士の映像閲覧・DM・SNS機能
- カメラ映像をAIで解析する集中度判定（プライバシー・精度・工数の観点で採用しない）
- 本格的な動画編集（前後カット以外）
- ネイティブアプリ（Webのみ）
