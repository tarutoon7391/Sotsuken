# ワーカーが Haiku のサブエージェントを使うときのルール（2026-10-08）

各ワーカー（w1〜w5）は、自分の作業に Haiku のサブエージェントを使ってよい。ごちゃごちゃにしないため、次を守る。

## 使ってよい場面
- **調べもの（読み取りのみ）**：契約（docs/04・03）とコードの照合、影響範囲の洗い出し、似た実装の検索、規約チェック
- **編集**：担当範囲の中で、ファイルがはっきり分かれている作業（例：A.jsx と B.css を別々の体に）

## 起動するとき
1. `model: "haiku"` を必ず指定する
2. 同時に動かすのは **1タブ5体まで**（2026-10-08 トーンさんの判断で 3 → 5 に変更。上限 20 は各セッションごとの値）
3. プロンプトに必ず書くこと：
   - 作業するフォルダ＝**自分の worktree の絶対パス**
   - 読んでよい／編集してよいファイルの一覧（編集させない体には「編集・作成は一切禁止」）
   - 照合元（docs/04 の節、CLAUDE.md など）
   - 返してほしい形式（行番号付き、件数、要確認は別枠）

## サブエージェントにさせないこと（プロンプトに「禁止」と明記する）
- **git 操作すべて**（commit・merge・checkout・branch・stash・push など）
- 自分の worktree の外（main のフォルダ、他のワーカーの worktree）を触ること
- `shared/`・`docs/04`・`docs/03`・マイグレーション・`package.json`・lockfile の変更、`npm install`
- サーバーの起動、DB に書き込むテスト（e2e・スモーク）の実行。これらはワーカー本人が実行する
- 他のワーカーや manager へのメッセージ送信。外とのやり取りはワーカー本人だけがする
- 契約に無い API・イベントの追加

## 編集を任せるとき
- **1つのファイルは1体だけ**が触る。同じファイルを2体に渡さない
- 同時に編集させるのは **2体まで**。3体目は読み取り専用にする
- 返ってきたら、ワーカー本人が差分を読んで理解してから取り込む（CLAUDE.md「理解していないコードをコミットしない」）
- build・jest は、取り込んだあとでワーカー本人が回す

## 報告
- 完了報告に「サブエージェント：n体（調べもの x／編集 y）」を1行入れる
- サブエージェントの指摘で、契約の解釈に迷うものは、自分で決めずに @manager へ上げる
