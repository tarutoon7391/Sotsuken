# 「カメラが付けられない」切り分け手順（2026-10-29）

班員テストで「カメラが付けられない」と報告があった件の原因切り分け。**(a)→(b)→(c)→(d) の順**に実施し、最初に NG になった項目で止めて結果を報告する（NG の項目が原因の第一候補）。

担当：W3（手順作成・集計・修正）／ テスト担当：班員（連絡はトーンさん経由）

## 先に知っておくこと（画面での見え方）

生徒の授業画面（LessonLive）では、カメラは次の条件がそろったときだけ先生に届く。

1. サーバーが LiveKit のトークンを返している（環境変数が設定済み）
2. 授業が `live`（`preparing` の間は LiveKit に接続しない＝待機画面では自分の確認用プレビューだけ）
3. ブラウザがカメラを許可している（https または localhost）

2 や 1 が欠けると、**ボタンを押してもエラーが出ず「何も起きない」ように見える**ことがある。そのため下の手順で順に確認する。

画面に出るエラー文と意味：

| 画面の文言 | 意味 |
|---|---|
| カメラの使用が許可されていません | ブラウザ／OS がカメラを拒否している → (b) |
| カメラが見つかりません | カメラ機器が無い／認識されていない → (b) |
| カメラを開始できませんでした | https でない、他のアプリ／タブがカメラを使用中、など → (b) |
| 映像を送信できませんでした | カメラは取れたが LiveKit への送信に失敗 → (c) |

---

## (a) サーバーの LiveKit 設定（Railway production）

**担当：Railway を触れる人（トーンさん）**

### a-1. 環境変数

- 見る場所：Railway → 対象サービス → Variables
- 見るもの：`LIVEKIT_URL` / `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` の 3 つ
- OK：3 つとも値が入っている（`LIVEKIT_URL` は `wss://…livekit.cloud` の形）
- NG：どれか 1 つでも空・未定義 → **環境の問題**。LiveKit Cloud のプロジェクト設定画面の値を入れて再デプロイ
- 補足：値そのものはチャットに貼らない（シークレット）。「入っている／いない」だけ報告

### a-2. トークン API の応答

1. production に先生または生徒でログインした状態のブラウザで、授業画面を開く
2. DevTools（F12）→ Network → フィルタに `token` → 授業画面を再読み込み
3. `POST /api/lessons/<id>/token` をクリック → Response タブを見る
- OK：`token` に長い文字列、`url` に `wss://…` が入っている
- NG（`"token": null, "url": null`）：a-1 の未設定 → **環境の問題**
- NG（403）：その授業のクラスに所属していないアカウント → テスト条件の問題
- NG（401）：ログイン切れ → ログインし直して再確認

## (b) ブラウザのカメラ許可

**担当：テスト班員**。カメラが付けられない端末・ブラウザで行う。

### b-1. https か

- 見るもの：アドレスバーが `https://` で始まっているか（`http://` の IP アドレスは不可。`localhost` は可）
- OK：`https://`（鍵アイコン）
- NG：`http://` → **環境の問題**（カメラは https でないと使えない。URL を https のものに）

### b-2. ブラウザのサイト許可

- 見るもの：アドレスバー左のアイコン（鍵／設定アイコン）→「カメラ」
- OK：「許可」
- NG：「ブロック」→ 「許可」に変更してページを再読み込み。それで付いたなら **許可設定の問題**
- 待機画面に「ブラウザでカメラを許可してください」の案内が出ている場合も同じ

### b-3. OS 側の許可

- Windows：設定 → プライバシーとセキュリティ → カメラ →「カメラへのアクセス」と「デスクトップアプリがカメラにアクセスできるようにする」が ON、使用ブラウザが ON
- Mac：システム設定 → プライバシーとセキュリティ → カメラ → 使用ブラウザが ON
- OK：ブラウザが ON
- NG：OFF → ON にしてブラウザを再起動。付いたなら **OS 設定の問題**

### b-4. カメラ単体で動くか（アプリと切り分け）

- 手順：別タブで `https://webcamtests.com/` などのカメラ確認サイトを開き、カメラを許可
- OK：自分の映像が映る → カメラ機器と許可は正常。(c) へ
- NG：映らない／使用中と出る → 他のアプリ（Zoom・Teams 等）や別タブがカメラを占有していないか確認。閉じても映らなければ **端末・機器の問題**

## (c) console / network のエラー

**担当：テスト班員**。DevTools（F12）を開いたまま、授業画面で「カメラを ON」を押す。

### c-1. トークン取得

- 見る場所：Network → `token`
- OK：ステータス 200 で `token` / `url` が入っている
- NG：`token: null` → (a) へ戻る（**環境の問題**）／ 4xx・5xx → ステータスと Response を控える（**サーバー側の問題**）

### c-2. LiveKit への接続

- 見る場所：Network → フィルタ `WS`（WebSocket）、または Console
- OK：`wss://…livekit.cloud/rtc?...` が Status `101` で接続され、授業画面の接続表示が「接続済み」
- NG：接続が失敗（赤）／Console に `could not establish signal connection` や `Failed to fetch` → `LIVEKIT_URL` の値違い、トークン期限切れ（6 時間）、社内・学校ネットワークの WebSocket／UDP 遮断を疑う。**環境の問題**（別回線＝スマホのテザリングで再現するか確認）

### c-3. publish（映像送信）

- 見る場所：画面の赤字、Console
- OK：「カメラを ON」を押すと「先生にだけ届きます」の表示が出る。先生側に映像が出る
- NG：赤字「映像を送信できませんでした」→ Console の赤いエラー全文を控える。**コードまたは LiveKit 権限の問題の可能性**（トークンの publish 権限は生徒＝カメラ・マイクのみ許可の設計）
- NG：赤字「カメラの使用が許可されていません」「カメラが見つかりません」「カメラを開始できませんでした」→ (b) へ

---

## (d) 授業が live か

**担当：先生役／テスト班員**

- 見るもの：授業画面の表示、または先生画面の状態（「準備中（preparing）」／「授業中（live）」）
- OK：先生が「授業開始」を押して **live** になっている状態の授業画面（`/learn/.../live` 相当）で試している
- NG：まだ `preparing`（待機画面）→ **仕様どおり**。待機画面のカメラは自分の確認用プレビューで、LiveKit には接続せず誰にも送らない。先生が授業を開始してから試す
- 補足：授業が `live` でも (a) が NG（token が null）だと、接続されず「ONにしても何も映らない」状態になる

## 結果の見方（W3 側の判断）

| 状況 | 判定 | 対応 |
|---|---|---|
| (a) NG | 環境 | Railway の変数設定を報告（コード修正なし） |
| (b) NG | 端末・ブラウザの設定 | 班員に設定手順を案内 |
| (c) 接続失敗 | ネットワーク／環境 | 別回線で再確認、必要なら設定を報告 |
| (c) 映像を送信できませんでした／全員で再現 | コード | W3 が修正して報告 |
| (d) preparing | 仕様 | テスト手順を周知 |
